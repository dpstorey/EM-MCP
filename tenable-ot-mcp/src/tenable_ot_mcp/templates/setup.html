1 — Connect to Tenable OT Security or Enterprise Manager

Use your direct ICP appliance URL or Enterprise Manager URL. The server posts setup validation GraphQL to <url>/graphql. Site-level routing is selected per query tool call using site_uuid or site_name.
Generated in Tenable OT Security / EM under Settings → User Management → API Keys. Use a service account, not a personal account.
Leave on unless your Tenable OT/EM endpoint uses a self-signed certificate.

2 — Choose what AI clients can do

Off by default — leave off for a read-only deployment.
⚠ Read this before enabling. Write tools mutate live state in your Tenable OT deployment. Anyone who holds the bearer token (or any AI client you connect with that token) can take these actions. Each tool defaults to dry_run=true, but the AI is allowed to call again with dry_run=false on its own — your operator workflow is the only thing that prevents an AI from applying changes you didn't intend.
  • Asset state: hide / restore / mark assets pending deletion, recalculate risk, create / update / archive asset groups (tags).
  • Detection coverage: enable / disable / archive detection policies (single and bulk). Disabling a policy stops it from firing; misuse creates real visibility gaps.
  • Findings: bulk-resolve findings matching a filter — closing alerts you may not have triaged.
  • Active scans: define / edit / enable / disable / delete scan jobs. The server defines them; a human operator runs them from the Tenable OT UI. Active scanning has caused operational incidents on legacy PLCs in the wild.
You can change this later by deleting /data/config.enc and re-running setup. Until then, treat the bearer token as you would a service-account password with these capabilities.
